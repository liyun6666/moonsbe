## 二、项目解决的问题

SBE 通过已有 XML Schema 定义消息的字段、类型、布局和版本。使用 SBE 的系统需要各语言的实现遵守同一 wire format，才能交换二进制消息。

moonsbe 提供可被其他 MoonBit 项目直接导入的 Schema 编译、编码、解码与代码生成接口。开发者可以复用现有消息定义，生成 MoonBit 结构体、枚举与编解码适配器，并对消息定义升级进行检查。该能力可服务于多种采用 SBE 的业务系统。

## 三、实用场景

1. **跨语言服务通信**：现有 Java 系统根据 SBE Schema 编码消息，MoonBit 服务使用同一 Schema 解码并读取字段。反向发送时由 MoonBit 编码，交给 Java 参考实现读取并校验。
2. **已有二进制记录读取**：调用方从文件、日志或消息队列获得一条消息的完整边界，库检查消息头、字段范围和长度，CLI 将内容导出为 JSON，供开发人员核对和转换。
3. **协议集成与版本回归验收**：开发团队比较新旧 Schema，检查固定字段追加、值域变化、重复组和变长字段变化，再在 CI 运行跨语言对照测试，保存消息文件与执行日志。

当前验证使用上游公开样例，项目尚无外部用户采用记录。

## 五、运行与验收步骤

### 环境

- MoonBit 编译器 `v0.10.17+d971670cd`，本地 moon 版本为 `0.1.20261023`。
- CLI 使用 Node.js，CI 固定 Node.js 22。
- Java 参考互通检查使用 JDK 24。
- 代码统计脚本需要 ripgrep。
- 首次解析依赖和下载参考 JAR 需要联网。

### 获取项目与运行测试

```sh
git clone https://github.com/liyun6666/moonsbe.git
cd moonsbe
moon update
moon fmt --check
moon check --target js --warn-list=-implicit_impl_as_method --deny-warn
moon test --target js --warn-list=-implicit_impl_as_method --deny-warn
moon test --target wasm-gc -p liyun6666/moonsbe --warn-list=-implicit_impl_as_method --deny-warn
```

当前代码的两种后端均应报告 `38` 个测试通过。`implicit_impl_as_method` 对应固定工具链的派生方法迁移告警，其余告警作为错误处理。

### 检查标准 Schema 并编码、解码消息

```sh
moon run cmd/main --target js --warn-list=-implicit_impl_as_method -- schema interop/upstream/example-schema.xml
moon run cmd/main --target js --warn-list=-implicit_impl_as_method -- encode interop/upstream/example-schema.xml 1 examples/car.json car.bin
moon run cmd/main --target js --warn-list=-implicit_impl_as_method -- decode interop/upstream/example-schema.xml car.bin
```

预期 Schema 的 `schemaId` 为 `1`，Car 模板编号为 `1`，固定区长度为 `45`。编码后的消息包含 `8` 字节标准头部，总长度为 `207` 字节。

### 生成并编译 MoonBit 类型

```sh
moon run cmd/main --target js --warn-list=-implicit_impl_as_method -- generate interop/upstream/example-schema.xml generated/car/messages.mbt
moon fmt generated/car
moon check --target js --warn-list=-implicit_impl_as_method --deny-warn
```

生成的类型包含 `Car`、复合字段、枚举和重复组记录。生成适配器使用共享的动态校验运行时，Schema 随生成源码嵌入并在包初始化时编译一次。

### 执行独立跨语言验收

```sh
moon run tools/interop.mbtx
```

脚本将依次执行以下验证。

1. 核验固定版本参考 JAR 的 SHA-256。
2. 使用上游工具和未修改的官方示例生成 Java 消息。
3. 使用 MoonBit 解码，将全部字段与预期 JSON 比较。
4. 使用 MoonBit 从输入 JSON 编码，由 Java 参考编码器产生期望字节并逐字节比较。
5. 使用 Java 生成解码器遍历完整消息，包括嵌套重复组及变长字段。
6. 生成、编译 MoonBit 类型，并由独立消费包解码和重新编码。
7. 再由 Java 验证消费包输出的完整消息。

成功时脚本输出 `PASS`，执行日志位于 `_build/interop-logs`。

## 七、兼容范围与限制

首版按仓库中的兼容矩阵交付。支持标准 `8` 字节消息头、双字节序、基础类型、常量、枚举、位集合、复合类型、嵌套组、变长数据和限定的版本处理。

扩展消息头、扩展组维度、版本化复合成员、可选数组及可选复合类型会返回不支持错误。未知枚举值和集合位按严格模式拒绝。旧 Schema 无法跳过的新增变长字段会触发完整消息检查错误。完整 SBE XSD 合规验证由独立标准工具承担。

当前已验证的外部实现为 Java。性能基准与其他语言实现的互操作验证尚未完成。具体支持项和资源上限见[兼容范围文档](compatibility.md)。
